01 / 触る設定は、役割の違う2つ

入力・整形

.editorconfig

Lua / Luau を「スペース2個」で字下げする、repo 共通の指定です。

Neovim の EditorConfig、Zed、StyLua が読みます。StyLua 専用の設定ファイルは追加していません。

補完・診断・型情報

.luarc.json

LuaLS に「どのコードや型定義を知っておくべきか」を伝えます。

Neovim と Zed から起動する LuaLS が読みます。エディタごとの同じ設定の重複を避けています。

一括整形の対象・除外は、既存の flake/formatter.nix にあります。Matugen などのテンプレートはここで除外します。専用の .styluaignore は置きません。

02 / 実行する仕組みと、読む仕組み

Neovim は設定の Lua を実行してプラグインを動かします。一方、LuaLS はソースと注釈を読んで、補完候補や診断をエディタへ返します。Zed で Neovim の設定を開いても、Neovim のプラグインは実行されません。

名前仕事動く場所
nvimx / Nixlock に固定したプラグインを用意し、Neovim と共通の型定義を配置する。ビルド・設定適用時
lazy.nvimプラグイン定義を読み、指定したタイミングでロードして設定する。Neovim 内
lazydev.nvimNeovim から使う LuaLS に、必要なライブラリを動的に知らせる。Neovim 内
LuaLSLua の構文、変数、型、API を解析して補完・診断を返す。エディタが起動する別プロセス
StyLuaLua を読み直し、整った書式へ書き換える。Zed の保存時・整形コマンド実行時

共通ライブラリの生成元は Neovim の Nix 設定 です。既存の nvimx の成果物から Lua ディレクトリだけをまとめるため、別バージョンの型定義を追加で取得する必要がありません。

03 / 型注釈は、LuaLS に渡す説明書

---@type LazySpec
return {
  "nvim-lualine/lualine.nvim",
  event = "VeryLazy",
  opts = { options = { theme = "catppuccin-nvim" } },
}

---@type LazySpec は「次の値は LazySpec という型として扱って」と LuaLS に伝えます。Lua の実行時にはコメントとして無視されます。プラグインをロードしたり、値を変換したり、実行時に検証したりはしません。

LazySpec という名前の定義は、lazy.nvim の lua/lazy/types.lua にある ---@alias から来ます。LuaLS がこのファイルを読めないと、注釈の名前だけが見えて「未知の型・エイリアス」と診断します。

注釈伝える内容例
@typeこの値の型---@type LazySpec
@class型の名前や構造を定義する---@class snacks.dashboard.Config
@alias既存の型・型の組み合わせに名前を付ける---@alias LazySpec ...
@param / @return関数の引数と戻り値の型---@param str string
グローバル変数と型名は別です。
diagnostics.globals に Snacks を登録すると「この変数名は存在する」と伝えられますが、その API の構造までは分かりません。LazySpec をここに登録しても型定義の代わりにはなりません。型を解決するには、定義元をライブラリとして読む必要があります。

この repo では、プラグイン定義の戻り値に LazySpec を付けています。Dashboard のような設定データや LSP 設定には、その値に対応する型を付けています。同じ注釈名を全ファイルへ貼るのではなく、値の役割に合わせています。

04 / なぜ lazydev だけでは足りなかったか

lazydev は Neovim のプラグインです。Zed でファイルを開いても、lazydev によるライブラリ登録は起きません。そのため、Zed が使う LuaLS にも明示的な参照先が必要でした。

さらに、LuaLS は同じ設定キーに対して次の順序を優先します。ライブラリ配列が自動で足し合わされると思うと、期待と食い違います。

  1. --configpath で指定した設定ファイル
  2. ワークスペースの .luarc.json
  3. エディタから渡された設定（lazydev が渡す設定もこの側）

元のルート設定には Hyprland の stub だけが workspace.library に入っていました。これが lazydev のライブラリ指定より優先され、Neovim 用の定義を読めなくする原因になっていました。

"workspace.library": [
  "/run/current-system/sw/share/hypr/stubs",
  "~/.local/share/nvim/lua-library",
  "${3rd}/luv/library"
]

現在はルート設定に Hyprland と Neovim の両方の参照先があります。${3rd}/luv/library は LuaLS に同梱された libuv の型定義です。Neovim 用の入れ子の .luarc.json と、重複した LuaLS グローバル設定は置いていません。

この repo のライブラリ指定は .luarc.json が担当します。lazydev は引き続き、共通の静的設定がない別の Neovim 関連プロジェクトなどで、必要な型を動的に登録する役目を持ちます。

05 / 自分の repo はスペース。外では、その repo に従う

root = true

[*.{lua,luau}]
indent_style = space
indent_size = 2

この .editorconfig は repo 配下の Lua / Luau に適用されます。Neovim には EditorConfig の読み込み機能があり、guess-indent は EditorConfig の字下げ指定があると、それを優先して推測で上書きしません。

外部の repo では、その repo の EditorConfig があれば従います。指定がなければ guess-indent がファイルを調べ、タブならタブ、スペース4個なら4個に合わせます。新規ファイルなど推測材料がない場合は、Neovim の既定設定であるスペース2個が出発点です。

タイミング担当起きること
入力するEditorConfig・guess-indentTab キーや改行時に、どう字下げを挿入するかを決める。
整形するStyLua既存のコードを解析し、スペース2個の書式へ書き換える。
空白を見るNeovim の list / listchars既存のタブや行末空白に表示用の記号を付ける。

expandtab を有効にしても既存タブは変換されません。今回の置換は StyLua による整形で行っています。Zed は保存時に StyLua を使いますが、Neovim に Lua の保存時自動整形は追加していません。

# テンプレートを除外して Lua を一括整形
nix fmt -- --formatters stylua

# 書き換えず、整形済みか確認
nix fmt -- --fail-on-change --formatters stylua

テンプレートは素の Lua ではないため、一括整形には除外設定を持つ treefmt を使います。通常の Lua ファイルを直接 StyLua で整形する場合も、字下げ指定は同じ EditorConfig から読みます。

06 / 疑問と確認方法

$schema の URL に vscode-lua とあるのはなぜ？

LuaLS の設定ファイルを説明する JSON Schema が、そのリポジトリに置かれているためです。設定名の補完や値の検証に使われます。VSCode を使う設定でも、VSCode 分岐を有効にする指定でもありません。

削除した vim.g.vscode の分岐は何をしていた？

VSCode の Neovim 拡張内で動く場合に、補完・LSP・UI などを通常の Neovim と切り替えるための分岐でした。この使い方をしないため削除しています。Zed で設定ファイルを編集することとは関係ありません。

変更した Lua が、通常起動した Neovim に反映されない

この構成では Nix が設定を Nix store にコピーし、Neovim はそのスナップショットを読みます。作業ツリーを編集しただけでは適用済み設定は変わりません。Nix の設定を適用し、Neovim を再起動します。共通ライブラリの配置にも Home Manager の適用が必要です。

Zed で、まだ LazySpec が未知と言われる

~/.local/share/nvim/lua-library/lazy/types.lua が存在するか確認します。次に repo ルートの .luarc.json を確認し、Zed の Lua 言語サーバーを再起動します。この共通ライブラリは Nix 設定を適用した環境に配置されます。他の環境で clone しただけでは存在しません。

Neovim で実際の入力設定を確認したい

:verbose setlocal expandtab? shiftwidth? tabstop? でバッファの値と設定元を調べられます。:LazyDev は Neovim 内で lazydev が把握しているライブラリを調べる手段です。.luarc.json が優先する静的ライブラリとは分けて確認してください。

Ghostty の帯と lualine の色は、型設定と関係する？

それぞれ別の表示設定です。Ghostty は window-padding-color = background にして上端セルの色の延長を止めました。lualine は実在する catppuccin-nvim テーマを指定し、auto テーマへのフォールバックを解消しています。
