# hyprlock 下端ベルトレイアウトの設計

- 対象: `home-manager/desktop/hyprland/hyprlock.conf`、`home-manager/desktop/hyprland/scripts/lock/lock-clock.sh`、`home-manager/desktop/hyprland/lock-colors.template.conf`
- 合意日: 2026-07-10
- 先行文書: `docs/superpowers/specs/2026-07-10-hyprlock-clock-quiet-poster-design.md`（本文書が置き換える）
- 調査: `docs/superpowers/research/2026-07-10-hyprlock-design-survey.md`

## 前提となる調査結果

ghq 配下の 147 個の hyprlock 設定について、時計ラベル（font_size が 40 以上で最大のもの）と入力欄の `halign` と `valign` を機械的に集計した。

時計の配置は中央が多数を占める。
`center/center` が 88 件、`center/top` が 20 件で、両者で全体の 73% になる。
四隅（`left/top` 5 件、`left/bottom` 4 件、`right/top` 13 件、`right/bottom` 9 件）は合計 31 件、21% にとどまる。

ただしこの分布から設計上の含意を直接引き出すわけにはいかない。
`right/top` の 13 件は、その大半が hyprlock 公式の `assets/example.conf`（`font_size = 90`、label 3 個）とその派生である。
`right/bottom` の `font_size = 55`、label 2 個、image 1 個という組み合わせも 5 件が同一テンプレートの派生である。
中央スタックが多いのは、hyprlock の既定座標である `0, 0` から最も少ない手数で到達できるためであって、設計判断の結果ではない。
四隅 31 件のうち、独立した設計と見なせるものは 10 件前後しかない。

その 10 件前後を精読して得た事実を、以下の設計判断の根拠とする。

**隅の時計と中央の入力欄を両立させている設計は、両者を同じ端の帯に束ねている**：`xeji01/neulock` の kiev テーマは、入力欄を `position = 0, 35` の `valign = bottom` に、左下の時計ブロックを `35, 385` と `35, 415` の `valign = bottom` に置く。
水平方向だけを「左端が時計、中央が入力欄」と分業させ、垂直方向は共有する。
stockholm テーマは同じことを画面上端で行っている。

**時計ブロックの内側に短い罫線を引く実装は、精読した範囲に存在しない**：罫線を持つ設定（`AT0117/dots`、neulock の kiev と leipzig、`xeji01/hyprstellar`）はいずれも幅 400 から 1300 ピクセルの長い線として使い、ブロック内部の装飾ではなく画面を分割する構造線として置いている。
アクセント色を罫線に使う例も見つからなかった。

**アクセント色を数字ブロックの内部に差す実装は 3 件ある**：`vargalott/dotfiles` は時を黄、分を前景色にする。
`nithitsuki/dotfiles` は時を明色、分を灰色に落とす。
`Momen-Hamed/Arch-ZEM` は青の明度差で時と分を分ける。
区切り記号（`:`）に差し色する例はゼロだった。

**時刻と日付のサイズ比は 5 倍から 6 倍が最頻**：日付ラベルを持つ 8 件のうち 5 件がこの帯に入る。
行間（時刻と日付の position の差を時刻の font_size で割った値）は 0.45 から 1.2 に分布する。

**日付ラベルの字間を広げる実装はない**：neulock の全 24 テーマで `letter_spacing` の使用はゼロだった。

## 現状の問題

現在の設定は、左下に時計ブロック（時刻 98 ピクセル、短い罫線 72 × 3 ピクセル、日付 22 ピクセル）を置き、入力欄を `position = 0, -80` の `valign = center` に置いている。

この構成には視覚的な支点が 2 つある。
入力欄は `fade_on_empty` によって未入力時に消えるため、普段の画面は「隅に置き忘れた小さな塊」に見える。
時計と入力欄のあいだに、位置による関係が何もない。

橙の罫線は scrim の暗部に沈み、意図した構造の表示として機能していない。
そもそも先行実装がこの構成を支持していない。

## 採用する構成

### 下端ベルト

画面下端を 1 本の帯として使う。
時計ブロックを左端に、入力欄を中央に置き、どちらも `valign = bottom` にする。

束ねの規則を 1 つ置く。

- **ベルト規則**：入力欄の垂直中心を、日付行の垂直中心に合わせる。

この規則が、少数派である「隅の時計と中央の入力欄」という構図を成立させる唯一の構造である。
kiev が下端全幅の罫線で可視化していた帯を、罫線なしで座標だけによって示す。

時計ブロックは時刻と日付の 2 行だけで構成し、左端の x 座標を揃える。

### 罫線の削除

`shape` ウィジェットを削除する。
階層はサイズ比と行間だけで作る。

### 単色化

`$lock_accent` を hyprlock.conf から完全に除去する。
他に参照箇所がないため、`lock-colors.template.conf` と生成物からも該当行を削除する。

壁紙は暖色のイラストである。
時計に橙を足しても背景に溶けるうえ、時刻そのものが装飾に見える。
時計を無彩色寄りに保つことで、壁紙が主役に戻る。

残す色は 3 つとする。

- **`$lock_time`**：時刻の数字全体（`on_surface`）
- **`$lock_ampm`**：AM/PM（`on_surface_variant`。時刻より低いコントラスト）
- **`$lock_date`**：日付行全体（`on_surface` のアルファ 0.9）

曜日だけを別色にする現在の振る舞いをやめ、日付行を単色にする。

### タイポグラフィ

日付の `letter_spacing` を廃止する。
先行実装が字間ではなくサイズと配置で差をつけていることに合わせる。

時刻と日付のサイズ比は 5.5 前後を目標にする。
現在の 98 対 22（4.5 倍）では日付が重く、大小の関係ではなく 2 行に見える。

### 時刻フォントの決定手順

時刻のフォントは実機のスクリーンショットで比較して決める。
先行文書は Inter Display Medium を指定していたが、その選択に根拠は書かれていない。

比較する 3 つは次のとおりとする。
いずれも追加のパッケージなしで使える。

- **JetBrainsMono Nerd Font Medium**：先行実装の多数派。字幅が揃う
- **Inter Display Medium**：`nixos/core/fonts/default.nix` の `inter` に含まれる。neulock の kiev が使う Helvetica Neue Medium と同じ立ち位置
- **TeX Gyre Adventor**：ITC Avant Garde Gothic のクローン。幾何学的な数字がイラストの曲線と韻を踏む

プロポーショナルなフォントを選んだ場合、分が `11` から `22` に変わったときに時刻全体の幅が変わり、右端が揺れる。
Inter と TeX Gyre Adventor を採る場合は、`lock-clock.sh` の span に `font_features='tnum 1'` を指定して等幅数字を明示する。
実機で揺れないことを確認してから確定する。

### 追加モジュールを置かない

時計、日付、入力欄以外は置かない。

隅に時計を置く 7 個の設定では、アバター画像が 4 件、MPRIS の再生情報が 3 件、挨拶やユーザー名が 3 件、バッテリーが 2 件から 3 件という頻度で追加モジュールが載っている。
neulock はさらに極小のブランドタグ、下端全幅の罫線、画面を半分塗るパネル、`xray = true` による窓といった装飾語彙を持つ。

これらを採らない理由は、装飾が乗る地がないことにある。
neulock の装飾が成立しているのは、背景が単色か絵画かテクスチャだからである。
この壁紙は水彩調のイラストで、人物の顔、眼鏡、リボン、髪にすでに細かい情報が詰まっている。
罫線やパネルを足せばイラストの線と競合する。

## 変更対象

`hyprlock.conf` では、`shape` ブロックを削除し、時刻ラベルと日付ラベルのフォント、サイズ、位置を更新する。
入力欄を `valign = bottom` に移し、`size = 220, 40`、`outline_thickness = 0` にする。
`rounding`、`fade_on_empty`、`fade_timeout`、背景色は変更しない。

`lock-clock.sh` では、`time` モードの引数から `$lock_accent` を除く。
`date` モードは曜日の色分けと `letter_spacing` をやめ、`FRI / JUL 10` の書式のまま全体を `$lock_date` の単色で出力する。

`lock-colors.template.conf` と `lock-colors.conf` から `$lock_accent` の行を削除する。

背景画像、scrim、シャドウ、アニメーションは変更しない。

## 実機で確定する値

座標とサイズは `lock-preview.sh` のスクリーンショットで確定する。
出発点の候補値を次に置く。

| 要素 | 候補値 |
| --- | --- |
| 時刻サイズ | 100（Adventor を採る場合は 85 から 90） |
| 日付サイズ | 18 |
| 時計ブロックの左端 | x = 56 |
| 時刻の位置 | `56, 128`（left/bottom） |
| 日付の位置 | `56, 62`（left/bottom） |
| 入力欄 | `size = 220, 40`、`position = 0, 62`（center/bottom） |

入力欄の y 座標は、ベルト規則によって日付行の中心と一致させる。
日付の位置を動かしたら、入力欄の y も同じ値に追従させる。

## 受け入れ基準

- 時計ブロックと入力欄がどちらも `valign = bottom` に置かれ、入力欄の垂直中心が日付行の垂直中心と一致する。
- `hyprlock.conf` に `shape` ブロックが存在しない。
- `$lock_accent` がリポジトリ内のどこからも参照されない。
- 時刻フォントは 3 候補のスクリーンショット比較を経て選ばれ、選定理由が本文書に追記されている。
- プロポーショナルなフォントを選んだ場合、`00` から `59` まで分を変えても時刻の右端が動かない。
- 時計、日付、入力欄以外のウィジェットが増えていない。
- `LOCK_CLOCK_AT=2026-09-23` のような長めの日付でも下端の表示が崩れない。
- `nix run .#build` と `nix run .#fmt -- --fail-on-change` が成功する。
