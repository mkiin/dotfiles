# treefmt の git pre-commit hook 設計

## 背景と目的

GitHub Actions の整形チェック（`nix run .#fmt -- --fail-on-change`）が失敗した。

```
ERRO file has changed path=lib/default.nix prev_size=3452 current_size=3503
formatted 172 files (1 changed) in 1.676s
Error: unexpected changes detected, --fail-on-change is enabled
```

原因は、コミット済みの `lib/default.nix` が `nixfmt-rfc-style` の整形ルールに従っていなかったことである。
cantarell-fonts のピン留め用 overlay 内の `inherit` 式が整形されておらず、CI で nixfmt が再整形した結果、差分が発生して `--fail-on-change` に引っかかった。
ログ中の `ERRO file has changed` は、treefmt が同じ `.nix` ファイルに nixfmt と statix を続けて走らせるため、片方の書き込み後にもう片方のキャッシュ済み stat とズレて出る副次的な警告であり、失敗の直接原因ではない。

未整形のファイルがそのままコミットできてしまう状態を塞ぐため、コミット時に treefmt を自動実行する git pre-commit hook を導入する。

## 現状

- `flake.nix` は `treefmtEval` を評価し、`packages.${system}.fmt` として treefmt ラッパーを出力済み。`nix run .#fmt` は利用可能。
- treefmt の定義は `lib/treefmt/default.nix` にあり、nixfmt / statix / shfmt / prettier / taplo / stylua を有効化している。
- git hook は未設定。`.git/hooks/` には何も置かれていない。
- direnv は未導入。home-manager の設定にも `programs.direnv` は無い。
- 既存の関連 spec として `2026-06-29-auto-fmt-hook-design.md` がある。これは Claude Code の PostToolUse hook で編集ファイルを整形するもので、git のコミット時整形とは対象が異なる。両者は併存する。

## 方針の決定事項

参考にした実装は `ghq/github.com/ryoppippi/dotfiles`。
ryoppippi は git hook の配線を 2 系統で持つ。

- flake-parts の `git-hooks.flakeModule` を使い、devShell の shellHook で `.git/hooks` に設置する系統。
- home-manager の `home.activation` で `.git/hooks/*` を直接書き出す系統。

後者は devShell にも direnv にも依存せず、`home-manager switch` の度に hook を設置する。
このリポジトリは direnv を導入しておらず、switch は日常的に実行するため、home.activation 方式を採る。

決定事項は次のとおり。

- hook 設置方法：home-manager の `home.activation` で `.git/hooks/pre-commit` を生成する。devShell / direnv は使わない。
- hook の挙動：自動修正型。`--fail-on-change` を付けずに `nix run .#fmt` を走らせ、ファイルを実際に整形してから再ステージし、コミットを続行する。treefmt 自体が失敗したときのみコミットを中止する。
- 対象範囲：pre-commit のみ。ryoppippi にある post-commit 等の自動 `nix run .#switch` 系フックは含めない。
- リポジトリの場所：`extraSpecialArgs` には追加せず、モジュール内で `config.home.homeDirectory` と `config.home.username` から導出する。
- ファイル配置：`home-manager/cli/git/git-hooks.nix` に置き、`home-manager/cli/git/default.nix` の `imports` に追加する。

## 構成

3 つの変更からなる。

### 1. `lib/default.nix` の整形

cantarell-fonts overlay の `inherit` 式を nixfmt-rfc-style の形に整形してコミットする。
CI を即時復旧させる。
整形は `nix run .#fmt -- lib/default.nix` の結果をそのまま採用する。

### 2. `home-manager/cli/git/git-hooks.nix`（新規）

`config` から dotfiles リポジトリの絶対パスを導出し、`home.activation` で pre-commit hook を書き出す。

```nix
{ config, lib, ... }:
let
  dotfilesDir = "${config.home.homeDirectory}/ghq/github.com/${config.home.username}/dotfiles";
in
{
  home.activation.installGitHooks = lib.hm.dag.entryAfter [ "writeBoundary" ] ''
    DOTFILES_DIR="${dotfilesDir}"
    if [ -d "$DOTFILES_DIR/.git" ]; then
      mkdir -p "$DOTFILES_DIR/.git/hooks"
      cat > "$DOTFILES_DIR/.git/hooks/pre-commit" << 'HOOK_EOF'
    #!/usr/bin/env bash
    # Generated by home-manager/cli/git/git-hooks.nix
    # staged ファイルに treefmt を適用する
    ...
    HOOK_EOF
      chmod +x "$DOTFILES_DIR/.git/hooks/pre-commit"
    fi
  '';
}
```

pre-commit 本体の挙動は ryoppippi 版を踏襲する。

- staged ファイルが無ければ即 `exit 0`。
- unstaged 変更と未追跡ファイルがあれば `git stash --keep-index --include-untracked` で退避する。staged の内容だけを整形し、無関係なファイルの巻き込みを防ぐ。
- `nix run .#fmt` を実行する。`--fail-on-change` は付けない。
- 整形で変わった可能性のある staged ファイルを `git add` で再ステージする。
- 退避した変更を `git stash pop` で戻す。
- treefmt が失敗していたら `exit 1` でコミットを中止する。それ以外は `exit 0`。

`dotfilesDir` の導出式は `lib/default.nix` の `dotfilesDirOf`（`${homeDir}/ghq/github.com/${username}/dotfiles`）と同じである。
`config.home.homeDirectory` と `config.home.username` は `homeBase` で設定済みのため確実に取れる。

### 3. `home-manager/cli/git/default.nix` への import 追加

新規モジュールを git モジュールの `imports` に加える。

```nix
{
  imports = [ ./git-hooks.nix ];
  # 既存の programs.git / programs.delta はそのまま
}
```

`home-manager/cli/git/default.nix` は現状 `{ config, ... }:` を引数に取る単一の attribute set のため、`imports` を持てるよう構造を調整する。

## 動作フロー

1. `home-manager switch` を実行する。
2. `installGitHooks` activation が走り、`.git/hooks/pre-commit` を生成する。
3. 以後 `git commit` のたびに pre-commit が発火する。
4. staged ファイルに `nix run .#fmt` が適用され、整形済みの内容で再ステージしてコミットが進む。
5. 未整形のままコミットされることが無くなり、CI の整形チェックが失敗しなくなる。

## 想定される影響と留意点

- hook が設置されるのは初回の `home-manager switch` 以降である。それまでの間は CI 側の `nix run .#fmt -- --fail-on-change` が整形を担保する。既存の CI ワークフローはそのまま残す。
- 自動修正型のため、コミットに含まれる内容が自分で stage したものと整形差分の分だけ変わる。意図した挙動である。
- `nix run .#fmt` は flake 評価を伴うため、コミット時に初回はやや時間がかかる。
- treefmt が構文エラー等で失敗した場合はコミットが中止される。整形のしようがないため正しい挙動である。
